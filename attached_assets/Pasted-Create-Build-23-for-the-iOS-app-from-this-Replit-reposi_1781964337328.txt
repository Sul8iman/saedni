The ONLY purpose of Build 23 is adding Push Notifications for Admin when an OTP code is requested, while keeping the notification system unified and reliable.

====================================================

1. UNIFIED NOTIFICATION SYSTEM
   ====================================================

Use the same notification infrastructure for all push notifications:

* Use Expo Push Notification Service for both:

  * helper request notifications
  * admin OTP notifications

* Use the same deduplication logic for both:

  * never send two notifications to the same Expo Push Token for the same event
  * deduplicate by expo_push_token
  * deduplicate by event ID / request ID / OTP notification ID

* Keep notification dispatch logic organized in one reusable server-side utility/module if possible.

* Do not create separate inconsistent notification systems.

====================================================
2. REGISTER ADMIN FOR PUSH NOTIFICATIONS
========================================

When an admin logs into the app:

* Request notification permission.
* Generate Expo Push Token.
* Save/update the admin Expo Push Token in the production database.

If multiple admin devices exist, all active admin devices should receive notifications.

====================================================
3. SEND PUSH TO ADMIN WHEN OTP IS REQUESTED
===========================================

Whenever any user requests a new OTP code:

Send a push notification to every active admin device.

Notification title:

طلب رمز تحقق جديد

Notification body example:

قام مستخدم بطلب رمز تحقق جديد.
اضغط لعرض بيانات المستخدم.

Notification data should include:

* notificationType = otp_request
* userId if exists
* phone
* requestTime
* otpNotificationId if available

====================================================
4. NOTIFICATION TAP
===================

When the admin taps the notification:

If userId exists:

Open the app directly to:

Admin → User Details

for that user.

If the user has not completed registration yet:

Open the fallback user details page showing:

* رقم الهاتف
* وقت طلب الرمز
* نوع الطلب: OTP
* رسالة:
  "لم يكتمل إنشاء الحساب بعد"

====================================================
5. MARK AS READ
===============

When the admin opens the notification:

* Mark notification as read.
* Update unread badge immediately.

====================================================
6. DUPLICATE PROTECTION
=======================

For every OTP request:

* Each admin device must receive exactly ONE push notification.
* Do not send duplicate pushes to the same Expo Push Token.
* If the OTP push function is called twice for the same OTP notification ID, skip the second call.

Apply the same duplicate protection style used for helper request notifications.
